# 개발 계획

promptcut의 개발 순서와 각 단계의 산출물을 정리한 문서입니다.

## 개발 순서

### 1. 기술 스택 확정

이미 결정된 선택을 문서로 고정합니다.

- 대상: macOS (Apple Silicon)
- 편집 엔진: Python + ffmpeg
- 화면: 웹 기반 UI(HTML/CSS/JS)를 Python 백엔드와 연결
- 데이터: 영상 메타데이터와 썸네일 캐시는 SQLite, 편집 계획과 프로젝트는 JSON 파일
- AI: 제공자 교체 가능한 구조. 첫 제공자는 Google AI Studio(Gemini) 무료 API

### 2. 설계서 작성

- 편집 계획 JSON 스키마 — 엔진과 나머지 계층 사이의 유일한 약속
- 모듈 경계 — 엔진, 저장 계층, AI 계획 계층, UI
- SQLite 스키마
- 처리 워크플로우 — 영상 추가부터 내보내기까지
- 화면 워크플로우 — 클립 선택, 대화 요청, 계획 확인, 렌더

### 3. UI 구현

목 데이터로 동작하는 화면을 만듭니다. 백엔드 없이 클릭과 패널 전환이 되는 상태까지.

- 영상 목록, 미리보기, 대화창, 타임라인
- 설정 패널 — 피사체 정보, 배경음악, 자막 스타일
- 다크 테마 기준

### 4. 편집 엔진 구현 + 단위테스트

- **클립 이어붙이기** — 이 프로그램의 핵심 기능입니다. 해상도, 프레임레이트, 코덱, 방향이 제각각인 클립을 하나의 기준으로 정규화한 뒤 이어붙입니다. 무음 클립에는 빈 오디오를 넣어 소리가 어긋나지 않게 합니다. 입력이 제각각이면 스트림 복사로는 이어붙일 수 없어 재인코딩이 필요하고, 그만큼 시간이 걸립니다.
- 촬영일 정렬, 순서 적용, 구간 자르기
- 자막 — 날짜, 나이, 직접 입력 문구
- 전환 효과, 색감 보정
- 배경음악 삽입과 음량 조절
- 명령줄 실행 지원 (JSON 입력 → 영상 출력)
- 단위테스트: 해상도와 방향이 다른 테스트 영상을 이어붙여 결과 검증

### 5. 저장 계층 구현 + 단위테스트

- SQLite — 영상 메타데이터, 썸네일 캐시
- JSON — 편집 계획, 프로젝트 파일 (버전 값 포함)
- 단위테스트: 입출력 왕복, 이전 버전 파일 읽기

### 6. AI 계획 계층 구현 + 단위테스트

- Gemini API 호출 (제공자별 파일로 분리)
- 응답 JSON 검증과 재시도
- 한도 초과 오류 처리
- 전송 범위: 촬영일, 길이, 파일명, 피사체 정보 등 메타데이터만
- 단위테스트: 잘못된 응답에 대한 검증 동작

### 7. UI와 백엔드 연결

- 파일 선택과 경로 전달
- 진행률, 오류, API 사용량 표시
- 미리보기 렌더와 내보내기

### 8. Mac 앱 패키징

- ffmpeg 포함 방식 결정
- 빌드 스크립트
- 첫 실행 경고 안내

### 9. 실제 영상으로 통합 테스트

실제 영상으로 전체 흐름을 확인하고 문제를 수정합니다.

## 알려진 위험

- **엔진 확인이 늦습니다.** UI를 먼저 만드는 순서라서 가장 위험한 부분(4번)을 늦게 확인합니다. iPhone 영상의 코덱이나 회전 정보 처리에서 문제가 나오면 설계가 흔들릴 수 있습니다. 엔진을 3번으로 올리는 선택도 있습니다.
- **미리보기 한계.** 자막과 색감까지 실시간으로 반영하기 어렵습니다. 짧은 저해상도 영상을 먼저 렌더해 확인하는 방식으로 갑니다.
- **AI 품질 미검증.** Gemini가 편집 요청을 정확한 계획으로 바꿔 주는지는 6번에서 실제로 확인해야 합니다. 부족하면 다른 제공자로 교체합니다.
- **무료 한도와 정책 변경.** Gemini 무료 단계의 한도와 데이터 이용 약관은 바뀔 수 있습니다.

## 순서 결정 기록

최초 순서는 UI 생성 → 설계서 작성 → DB 생성 → 워크플로우 생성 → 개발언어 선정 → 개발 → 단위테스트였습니다. 세 가지를 조정했습니다.

- 개발언어 선정을 맨 앞으로 옮김. UI를 만들려면 언어와 방식이 먼저 정해져야 합니다.
- 워크플로우 생성을 설계서에 합침. 따로 두면 두 문서가 어긋납니다.
- 단위테스트를 각 계층 구현 직후로 분산. 끝에 몰면 수정 비용이 커집니다.
